change-evidence

Evidence for pull requests written by agents, for Laravel and Next.js, published on npm.

Laravel and Next.js/Prisma policies · Studied on repositories it wasn't tuned on

Creator · 2026 – present · github.com/Semeton/change-evidence ↗

Business goal

Show a reviewer which parts of a 3,000-line agent pull request need careful reading.

Context

  • –Agents write pull requests faster than anyone can review them line by line, so review turns into skimming.
  • –The changes that matter most are rarely the biggest: a route that became public, a migration that retypes a column, a query that skips tenant scoping.

Trust boundary

Decisions

Never run the code it judges

It reads the pull request's commits as git objects and never checks out, installs, builds or executes them. The workflow runs from the base branch, so a pull request can't edit the check that judges it.

UNKNOWN is never a pass

Routes, migrations, dependencies and CI changes are extracted statically. Anything it can't establish is reported as UNKNOWN and raises the risk tier.

Policy as data, per repository

Built-in policies for Laravel and for Next.js with Prisma ship as data. A repository adds what only it knows, such as where its tenant boundary is and where money moves, read from the base branch and never from the pull request.

Route by consequence, and say what it can't show

The rules point reviewers at what matters: auth, schema, money, CI and the supply chain. A study mode replays merged pull requests against later reverts and bug fixes, and the validation report states its own limits: nothing yet shows the tool predicts defective PRs, and as a ranking it hasn't beaten PR size, which did better on one repository and was level on another.

Result

  • –Published as @semeton/change-evidence and running in shadow mode on Lawyering since November 2026: one report per pull request, never blocking a merge.
  • –Studied on BookStack and Documenso, which it was never tuned on, and on Lawyering, whose reports later shaped the rules: generated files are now excluded from size, and each report says what it didn't check.
